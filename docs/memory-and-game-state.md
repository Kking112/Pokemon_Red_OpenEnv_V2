# Memory and Game State

This document describes the memory subsystem that extracts structured game state
from the PyBoy Game Boy emulator at each environment step. The subsystem covers
RAM address definitions, binary decoding primitives, structured dataclasses, state
delta computation, and the event flags system.

---

## Overview

Pokemon Red stores all mutable game data in the Game Boy's 64 KB RAM address
space. The environment reads this RAM directly from PyBoy at the end of every
`step()` and `reset()` call to produce the `game_state` dictionary that is
included in every `PokemonRedObservation`.

The memory pipeline has three layers:

```
PyBoy RAM (raw bytes)
        |
        v
  MemoryReader          (pokemon_red_env/memory/reader.py)
  - Primitive reads     (byte, word, BCD, bit)
  - Pokemon helpers     (badges, party, event flags, Pokedex)
        |
        v
  GameState dataclass   (pokemon_red_env/memory/game_state.py)
  - PartyMemberState
  - ProgressState
  - BattleState
        |
        v
  to_observation_dict() (flat dict passed to the agent)
```

The `Addresses` class (`pokemon_red_env/memory/addresses.py`) is the single
source of truth for which RAM byte corresponds to which game variable. All three
layers depend on it exclusively.

---

## RAM Address Architecture

### Source of Truth: `pokered.sym`

The canonical Game Boy RAM layout for Pokemon Red (US) is derived from the
official disassembly symbol file located at:

```
Assembly_RAM_Addresses/pokered.sym
```

This file is generated by `rgblink` from the `pret/pokered` disassembly project
and contains every named symbol together with its bank and address. For example:

```
; File generated by rgblink
DA:DA41 wPlayTimeHours
D0:D057 wIsInBattle
D3:D35E wCurMap
```

Environment code never reads `pokered.sym` at runtime. Instead, the relevant
addresses were curated manually into the `Addresses` class, which is the only
file that environment code imports for address information.

### The `Addresses` Class

**File:** `pokemon_red_env/memory/addresses.py`

Every address is expressed as a frozen `AddressSpec` dataclass:

```python
@dataclass(frozen=True)
class AddressSpec:
    name: str         # Symbol name from pokered.sym (e.g. "wCurMap")
    address: int      # Absolute RAM address (e.g. 0xD35E)
    width: int = 1    # Byte width of the field
    encoding: str = "u8"  # How to decode: u8, u16_be, u16_le, u24_be, bcd, bitmask, struct
    description: str = ""
```

The `Addresses` class groups all specs by functional category:

| Category | Example symbol | Address | Notes |
|---|---|---|---|
| Player position | `wYCoord` | `0xD361` | 1-byte overworld tile Y |
| Player position | `wXCoord` | `0xD362` | 1-byte overworld tile X |
| Map | `wCurMap` | `0xD35E` | Map index (see `maps.json`) |
| Map | `wLastMap` | `0xD365` | Map before last transition |
| Map | `wCurMapTileset` | `0xD367` | Tileset index |
| Walk counter | `wWalkCounter` | `0xCFC5` | Walk animation frame counter |
| Party | `wPartyCount` | `0xD163` | 0–6 |
| Party slot 1 | `wPartyMon1` | `0xD16B` | 44-byte struct |
| Party slot 2 | `wPartyMon2` | `0xD197` | 44-byte struct |
| Party slot 3 | `wPartyMon3` | `0xD1C3` | 44-byte struct |
| Party slot 4 | `wPartyMon4` | `0xD1EF` | 44-byte struct |
| Party slot 5 | `wPartyMon5` | `0xD21B` | 44-byte struct |
| Party slot 6 | `wPartyMon6` | `0xD247` | 44-byte struct |
| Badges | `wObtainedBadges` | `0xD356` | 8-bit bitmask |
| Pokedex owned | `wPokedexOwned` | `0xD2F7` | 19-byte bitmask (151 bits) |
| Pokedex seen | `wPokedexSeen` | `0xD30A` | 19-byte bitmask (151 bits) |
| Play time | `wPlayTimeHours` | `0xDA41` | Hours elapsed in-game |
| Battle status | `wIsInBattle` | `0xD057` | 0=overworld, 1=wild, 2=trainer |
| Battle result | `wBattleResult` | `0xCF0B` | Outcome code |
| Enemy HP | `wEnemyMonHP` | `0xCFE6` | 2-byte big-endian |
| Enemy max HP | `wEnemyMonMaxHP` | `0xCFF4` | 2-byte big-endian |
| Enemy level | `wEnemyMonLevel` | `0xCFF3` | 1-byte |
| Enemy species | `wEnemyMonSpecies` | `0xCFE5` | 1-byte species index |
| Ally HP | `wBattleMonHP` | `0xD015` | 2-byte big-endian, active slot |
| Selected move | `wPlayerMoveNum` | `0xCFD2` | Move slot index |
| Bag items | `wNumBagItems` | `0xD31D` | Count of item stacks in bag |
| Money | `wPlayerMoney` | `0xD347` | 3-byte BCD |
| Box items | `wNumBoxItems` | `0xD53A` | Count of item stacks in PC box |
| Text box | `wTextBoxID` | `0xD125` | Current dialogue box |
| Menu cursor | `wCurrentMenuItem` | `0xCC26` | Menu selection index |
| Menu watched | `wMenuWatchedKeys` | `0xCC29` | Bitmask of watched input keys |
| Menu top Y | `wTopMenuItemY` | `0xCC24` | Top-left Y of displayed menu |
| Menu top X | `wTopMenuItemX` | `0xCC25` | Top-left X of displayed menu |
| Text speed | `wLetterPrintingDelayFlags` | `0xD358` | Text speed flags |
| Event flags | `wEventFlags` | `0xD747` | Start of event flag byte range |

The event flag range runs from `0xD747` (inclusive) to `0xD886` (inclusive), a
span of 320 bytes encoding up to 2560 individual boolean flags at the bit level.

#### Party Struct Layout

Each party member occupies `0x2C` (44) bytes starting at its base address. The
offsets used by the reader are:

| Offset | Field |
|---|---|
| `0x00` | Species index |
| `0x01` | Current HP (2 bytes, big-endian) |
| `0x04` | Status condition byte |
| `0x05` | Type 1 |
| `0x06` | Type 2 |
| `0x08` | Move 1 index |
| `0x0E` | Experience (3 bytes, big-endian) |
| `0x21` | Level |
| `0x22` | Max HP (2 bytes, big-endian) |

The convenience list `Addresses.PARTY_BASES` provides the six base addresses in
slot order for iteration.

## Memory Reader

**File:** `pokemon_red_env/memory/reader.py`

`MemoryReader` wraps a live `PyBoy` instance and exposes both primitive read
operations and higher-level Pokemon-specific helpers. It is instantiated once per
environment session inside `PokemonRedEnvironment.__init__()`.

```python
self.memory = MemoryReader(
    pyboy=self.pyboy,
    events_data_path=self.config.events_data_path_obj,   # events.json
    maps_data_path=self.config.maps_data_path_obj,       # maps.json
    curated_events_path=...,                             # curated_events.json
    event_flags_mode=self.config.event_flags_mode,       # "curated" | "all" | "none"
    event_flags_max_count=self.config.event_flags_max_count,
)
```

### Primitive Read Methods

All primitives read directly from `self.pyboy.memory[address]`.

#### `read_byte(address: int) -> int`

Reads a single unsigned byte. This is the lowest-level primitive; all other
methods are built on top of it.

```python
map_id = reader.read_byte(0xD35E)
```

#### `read_word(address: int, big_endian: bool = True) -> int`

Reads two consecutive bytes and combines them into a 16-bit integer. Defaults to
big-endian byte order, which is the convention used by most multi-byte fields in
Pokemon Red.

```python
enemy_hp = reader.read_word(0xCFE6, big_endian=True)
```

#### `read_bytes(address: int, length: int) -> bytes`

Reads `length` consecutive bytes starting at `address` and returns them as a
`bytes` object. Used internally for BCD decoding, experience extraction, and
Pokedex bitmask counting.

#### `read_bcd(address: int, length: int) -> int`

Decodes a Binary Coded Decimal value. Each nibble of each byte encodes one
decimal digit (high nibble first). Pokemon Red stores the player's money as a
3-byte BCD value at `wPlayerMoney` (`0xD347`).

```python
money = reader.read_bcd(0xD347, length=3)  # e.g. 0x003000 -> 3000
```

#### `read_bit(address: int, bit: int) -> bool`

Tests a single bit within a byte. `bit` must be in the range 0–7 where bit 0 is
the least significant bit. This is used for every event flag and badge
extraction.

```python
has_boulder_badge = reader.read_bit(0xD356, bit=0)
```

#### `read_custom(address: int, width: int, encoding: str) -> Any`

A generic dispatch method that routes to the appropriate primitive based on the
encoding string. Supported encodings:

| Encoding | Bytes | Decoding |
|---|---|---|
| `u8` | 1 | Single unsigned byte |
| `u16_be` | 2 | Big-endian 16-bit unsigned integer |
| `u16_le` | 2 | Little-endian 16-bit unsigned integer |
| `u24_be` | 3 | Big-endian 24-bit unsigned integer |
| `bcd` | `width` | Binary Coded Decimal |
| `bytes` | `width` | Raw byte string |

This method is used by any code that reads from an `AddressSpec` without wanting
to case-switch on encoding itself.

### Event Flag Reader

#### `read_event_flag(flag_name: str) -> bool`

Looks up the flag by name or ID in the loaded events table, then calls
`read_bit()` at the resolved address and bit position.

```python
started_adventure = reader.read_event_flag("followed_oak_into_lab")
got_starter = reader.read_event_flag("got_starter")
```

Raises `KeyError` if the name is not found in the loaded events table.

### Pokemon-Specific Helpers

#### Badge Decoding

`_decode_badges(bitmask: int) -> list[int]`

Expands the 8-bit badge bitmask at `wObtainedBadges` (`0xD356`) into a list of
eight integers (0 or 1), one per gym in game order: Boulder, Cascade, Thunder,
Rainbow, Soul, Marsh, Volcano, Earth.

```python
badges_bitmask = reader.read_byte(0xD356)
badges = reader._decode_badges(badges_bitmask)
# e.g. bitmask 0b00000011 -> [1, 1, 0, 0, 0, 0, 0, 0]
```

#### Pokedex Counting

`_pokedex_count(start: int, length: int) -> int`

Counts set bits across a multi-byte bitmask region. Used for both owned
(`wPokedexOwned`, `0xD2F7`, 19 bytes) and seen (`wPokedexSeen`, `0xD30A`, 19
bytes) Pokedex entries. Each bit represents one of the 151 species.

#### Party Extraction

`_extract_party_member(slot: int) -> PartyMemberState`

Reads all fields of one party member from the struct at `PARTY_BASES[slot]`,
applying the named offsets. HP and Max HP are 2-byte big-endian values;
experience is a 3-byte big-endian value assembled manually. Returns a
`PartyMemberState` instance.

#### Total Event Count

`_event_count() -> int`

Counts all set bits in the full event flag byte range `0xD747`–`0xD886`. This
aggregate count is used by the exploration novelty reward component.

### Data Table Loading

The reader loads three JSON files on construction:

| File | Loaded into | Usage |
|---|---|---|
| `events_data_path` | `_events_by_id`, `_events_by_name` | `read_event_flag()` lookups, `_extract_event_flags()` |
| `maps_data_path` | `_map_names` | Resolving `map_id -> map_name` string |
| `curated_events_path` | `_curated_event_names` | Ordered list for curated event flag mode |

Map names are accessed directly during `extract_game_state()`:

```python
map_name = self._map_names.get(map_id, f"Map {map_id}")
```

If the map ID has no entry in `maps.json`, the fallback string `"Map <id>"` is
used.

### Full State Extraction

`extract_game_state(...) -> GameState`

The primary entry point called every step. It reads all tracked addresses in a
single sequential pass over PyBoy RAM and assembles a fully populated `GameState`
instance. Parameters:

| Parameter | Type | Description |
|---|---|---|
| `step_count` | `int` | Current episode step index |
| `total_reward` | `float` | Cumulative episode reward so far |
| `seen_coords_count` | `int` | Number of unique (x, y, map) coordinates visited |
| `event_flags_mode` | `str \| None` | Override for the configured mode |
| `event_flags_max_count` | `int \| None` | Override for max number of flags |

## Game State Model

**File:** `pokemon_red_env/memory/game_state.py`

The module defines four dataclasses. The top-level `GameState` is returned by
`extract_game_state()` and converted to a flat dictionary by
`to_observation_dict()`.

### `PartyMemberState`

Represents one Pokemon in the active party.

```python
@dataclass
class PartyMemberState:
    species: int = 0   # Species index (1-151 in-game, 0 = empty slot)
    level: int = 0     # Current level (1-100)
    hp: int = 0        # Current HP
    max_hp: int = 0    # Maximum HP
    status: int = 0    # Status condition byte (0=none, see game docs)
    type1: int = 0     # Primary type index
    type2: int = 0     # Secondary type index (same as type1 if single type)
    move1: int = 0     # First move index
    exp: int = 0       # Total experience points (24-bit)
```

### `BattleState`

Represents the state of an active battle. All fields except `in_battle` are
`None` when the player is in the overworld.

```python
@dataclass
class BattleState:
    in_battle: int = 0            # 0=overworld, 1=wild battle, 2=trainer battle
    battle_outcome: int | None    # Result code when battle ends
    enemy_hp: int | None          # Enemy current HP
    enemy_max_hp: int | None      # Enemy maximum HP
    enemy_level: int | None       # Enemy level
    enemy_species: int | None     # Enemy species index
    battle_mon_hp: int | None     # Active ally HP (from wBattleMonHP)
    player_move_num: int | None   # Selected move slot index
```

The reader only performs battle-specific RAM reads when `in_battle != 0`,
avoiding unnecessary reads on every overworld step.

### `ProgressState`

Tracks long-term progression metrics.

```python
@dataclass
class ProgressState:
    badges: list[int] = [0] * 8      # Per-badge booleans, game order
    badge_count: int = 0              # Sum of badges list
    event_count: int = 0             # Total set bits in 0xD747-0xD886
    event_flags: dict[str, bool] = {} # Named flags (mode-dependent)
    pokedex_owned_count: int = 0      # Number of owned species
    pokedex_seen_count: int = 0       # Number of seen species
    play_time_hours: int = 0          # In-game hours from wPlayTimeHours
```

### `GameState`

The top-level container combining all subsystems.

```python
@dataclass
class GameState:
    # Player position and map
    player_x: int
    player_y: int
    map_id: int
    map_name: str       # Human-readable, resolved from maps.json
    map_tileset: int
    last_map: int
    walk_counter: int

    # Party summary
    party_count: int
    party: list[PartyMemberState]
    party_hp: list[int]
    party_max_hp: list[int]
    party_levels: list[int]
    party_hp_fraction: float  # sum(hp) / max(sum(max_hp), 1)
    level_sum: int            # sum of all party levels

    # Subsystems
    progression: ProgressState
    battle: BattleState

    # Inventory
    num_bag_items: int
    num_box_items: int
    player_money: int         # BCD-decoded integer

    # Menu / UI
    text_box_id: int
    current_menu_item: int
    menu_watched_keys: int
    top_menu_item_x: int
    top_menu_item_y: int
    letter_printing_delay_flags: int

    # Episode tracking
    seen_coords_count: int    # Unique (x, y, map_id) tuples visited
    step_count: int
    total_reward: float
```

### `to_observation_dict()`

Flattens the nested dataclass hierarchy into a single `dict[str, Any]` suitable
for inclusion in `PokemonRedObservation.game_state`. The hierarchy is collapsed
as follows:

- `progression.badges` -> `"badges"`
- `progression.badge_count` -> `"badge_count"`
- `progression.event_count` -> `"event_count"`
- `progression.event_flags` -> `"event_flags"`
- `progression.pokedex_owned_count` -> `"pokedex_owned_count"`
- `progression.pokedex_seen_count` -> `"pokedex_seen_count"`
- `progression.play_time_hours` -> `"play_time_hours"`
- `battle.*` -> flattened with the same field names
- `party` -> `"party"` as a list of `asdict(member)` dicts

All other `GameState` fields are emitted with their original names.

## State Delta Computation

**File:** `pokemon_red_env/server/environment.py`

State deltas give an agent explicit access to what changed since the previous
step, removing the need to compare consecutive observations manually.

### Delta Keys

The environment tracks changes across these seven scalar fields:

```python
_DELTA_KEYS: list[str] = [
    "player_x",
    "player_y",
    "seen_coords_count",
    "badge_count",
    "level_sum",
    "event_count",
    "player_money",
]
```

For each key `k` in `_DELTA_KEYS`, the delta is computed as:

```python
delta_k = current_state[k] - previous_state[k]
```

The resulting dictionary uses the prefix `delta_`: `delta_player_x`,
`delta_player_y`, `delta_seen_coords_count`, `delta_badge_count`,
`delta_level_sum`, `delta_event_count`, `delta_player_money`.

### Boolean Event Flags

Two boolean fields are appended to every delta dict:

| Key | Condition |
|---|---|
| `map_changed` | `curr["map_id"] != prev["map_id"]` |
| `battle_started` | `curr["in_battle"] > 0` and `prev["in_battle"] == 0` |

### Integration in `step()`

Deltas are computed and injected into `game_state` before the observation is
built:

```python
if self.config.include_state_deltas and self._prev_state_dict:
    game_state["state_deltas"] = self._compute_state_deltas(
        game_state, self._prev_state_dict
    )
else:
    game_state["state_deltas"] = {}
```

Deltas are disabled when `include_state_deltas = False` in `PokemonRedConfig`,
in which case `state_deltas` is always an empty dict. On `reset()`, `state_deltas`
is always empty because there is no prior step to compare against.

## Temporal Awareness

In addition to state deltas, each observation carries two fields that describe
what the environment experienced during the _previous_ step rather than the
current one. This helps agents correlate their prior action with its outcome
without requiring multi-step memory.

| Field | Type | Description |
|---|---|---|
| `prev_step_reward` | `float` | Scalar reward returned after the last `step()` call |
| `prev_action_name` | `str` | Human-readable name of the last action taken (e.g. `"up"`, `"a"`, `"noop"`) |

On `reset()`, both fields are zeroed/empty:

```python
game_state["prev_step_reward"] = 0.0
game_state["prev_action_name"] = ""
```

On subsequent steps, they reflect the prior step:

```python
game_state["prev_step_reward"] = self._prev_reward
game_state["prev_action_name"] = self._prev_action_name
```

The internal tracking variables `_prev_reward` and `_prev_action_name` are
updated at the end of each `_step_impl()` call, after reward calculation and
observation construction.

## Event Flags System

Pokemon Red uses a contiguous byte range from `0xD747` to `0xD886` (320 bytes,
2560 bits) to store boolean game event flags. Each bit records whether a specific
in-game event has occurred: receiving an item, defeating a gym leader, talking to
an NPC for the first time, etc.

### Three Modes

The environment exposes three modes for how event flags are collected and included
in the observation. The mode is set via `PokemonRedConfig.event_flags_mode`.

#### `"none"`

No event flags are extracted. `event_flags` in the observation is an empty dict.
Use this mode when minimizing observation size.

#### `"curated"`

Only the hand-selected flags listed in `curated_events.json` are read. This is
the default mode and the recommended choice for most training setups. The flags
correspond to major story milestones and are stable across ROM versions.

#### `"all"`

All flags found in `events.json` are read, up to `event_flags_max_count`. Entries
are sorted by `(address, bit, name)` for deterministic ordering. Use this mode
for research that requires comprehensive event coverage.

### Storage in RAM

Each event flag occupies exactly one bit. To read a specific flag:

1. Look up the flag's `address` and `bit` from `events.json`.
2. Call `read_byte(address)` to get the byte at that address.
3. Test `byte & (1 << bit)`.

Example for `followed_oak_into_lab` (bit 0 of address `0xD747` = 55111):

```python
byte = reader.read_byte(0xD747)   # Read byte at wEventFlags
flag = bool(byte & (1 << 0))     # Test bit 0
```

The `_event_count()` helper sums all set bits across the entire 320-byte range
to produce a single integer representing how many events have been triggered. This
is cheaper than reading individual flags by name and is used directly by the event
progress reward component.

### Fallback Behavior in Curated Mode

If `curated_events.json` is empty or missing, curated mode falls back to reading
up to `min(event_flags_max_count, 32)` flags from the alphabetically sorted keys
of the full events table.

## Data Tables

All data tables are stored as JSON files under `pokemon_red_env/data/`.

### `events.json`

A JSON array of event flag descriptors. Each entry has the following structure:

```json
{
  "id": "0xD747-0",
  "name": "followed_oak_into_lab",
  "description": "Followed Oak Into Lab",
  "address": 55111,
  "bit": 0
}
```

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique identifier: `"<hex address>-<bit>"` |
| `name` | `string` | Canonical event name; may be a placeholder like `"event_001"` for unnamed flags |
| `description` | `string` | Human-readable description |
| `address` | `int` | Absolute decimal RAM address |
| `bit` | `int` | Bit index within the byte (0–7, LSB = 0) |

This file is loaded into `_events_by_id` (keyed on `id`) and `_events_by_name`
(keyed on `name`) for O(1) lookups.

### `maps.json`

A JSON object mapping map index strings to location names:

```json
{
  "0": "Pallet Town",
  "1": "Viridian City",
  "12": "Route 1",
  "100": "SS Anne Kitchen",
  "118": "Hall of Fame"
}
```

The keys are string-encoded integers matching the values read from `wCurMap`
(`0xD35E`). At runtime, lookups are done against the integer-keyed
`_map_names` dict:

```python
map_name = self._map_names.get(map_id, f"Map {map_id}")
```

### `curated_events.json`

A JSON array of event flag name strings, ordered by expected game progression:

```json
[
  "followed_oak_into_lab",
  "got_starter",
  "got_pokedex",
  "oak_got_parcel",
  "got_oaks_parcel",
  "beat_brock",
  "beat_misty",
  "beat_lt_surge",
  "beat_erika",
  "beat_koga",
  "beat_sabrina",
  "beat_blaine",
  "beat_viridian_gym_giovanni",
  "beat_champion_rival",
  "got_hm01",
  "got_hm03",
  "got_hm04",
  "got_poke_flute",
  "got_bicycle",
  "met_bill"
]
```

Each name must correspond to a `name` field in `events.json`. If a name is not
found in the loaded events table at read time it is silently skipped; no error
is raised. This list is intentionally short (20 entries) to keep observation
size small and rewards interpretable.

## Extending the Memory System

Adding a new tracked RAM field requires changes in three files.

### Step 1: Add an `AddressSpec` to `Addresses`

**File:** `pokemon_red_env/memory/addresses.py`

Look up the symbol name in `Assembly_RAM_Addresses/pokered.sym` and add a new
class attribute:

```python
class Addresses:
    # ... existing entries ...

    # Example: track the current box number
    CURRENT_BOX_NUM = AddressSpec(
        "wCurrentBoxNum", 0xDA80, 1, "u8", "Current PC box number (0-11)"
    )
```

Choose the `encoding` string from the supported set: `u8`, `u16_be`, `u16_le`,
`u24_be`, `bcd`, `bytes`. Use `bitmask` or `struct` as descriptive labels for
complex fields that require custom reader logic.

### Step 2: Read the Field in `MemoryReader`

**File:** `pokemon_red_env/memory/reader.py`

Add a read call inside `extract_game_state()` and pass the value to the
`GameState` constructor:

```python
current_box = self.read_byte(Addresses.CURRENT_BOX_NUM.address)

return GameState(
    # ... existing fields ...
    current_box_num=current_box,
)
```

For multi-byte or specially-encoded fields use `read_custom()`:

```python
special_value = self.read_custom(
    Addresses.SOME_ADDRESS.address,
    width=Addresses.SOME_ADDRESS.width,
    encoding=Addresses.SOME_ADDRESS.encoding,
)
```

### Step 3: Add the Field to `GameState`

**File:** `pokemon_red_env/memory/game_state.py`

Add the field to the `GameState` dataclass and include it in `to_observation_dict()`:

```python
@dataclass
class GameState:
    # ... existing fields ...
    current_box_num: int = 0

    def to_observation_dict(self) -> dict[str, Any]:
        out = {
            # ... existing entries ...
            "current_box_num": self.current_box_num,
        }
        return out
```

For fields that belong logically to a subsystem (progression, battle, party),
add them to the appropriate sub-dataclass (`ProgressState`, `BattleState`,
`PartyMemberState`) and update both the sub-dataclass and the flattening logic
in `to_observation_dict()`.

After these three changes, the new field will appear in every
`PokemonRedObservation.game_state` dict automatically. No changes to the server,
reward system, or config are required unless the new field drives a reward
component or a configuration knob.
